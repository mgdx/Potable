# Revue F-Droid (mainteneur) — io.github.mgdx.potable 1.0.0 (1)

Revue statique seulement : la revue testeur (appareil, capture réseau,
permissions, VirusTotal) reste à faire. Les cases qui en dépendent sont
laissées vides et signalées dans « Non vérifié ». Brouillon de recette :
[`docs/fdroid/io.github.mgdx.potable.yml`](../fdroid/io.github.mgdx.potable.yml).

**Verdict.** À corriger avant soumission : le code est conforme, mais il n'y a
encore ni dépôt public ni tag de version.

**Points relevés.**
1. *Bloquant* — dépôt source non publié : `https://github.com/mgdx/Potable`
   répond 404, aucun `remote` configuré ; `SourceCode`, `Repo` et
   `IssueTracker` de la recette pointent dans le vide.
2. *Bloquant* — aucun tag `v1.0.0` (seuls `sprint-1` … `sprint-6` existent) :
   `commit: v1.0.0` et `UpdateCheckMode: Tags` n'ont rien à résoudre.
3. *Non bloquant* — `gradle/wrapper/gradle-wrapper.jar` est un jar officiel,
   mais celui de Gradle 9.0.0 / 9.1.0 (SHA-256 `76805e32…95493f3`), pas celui
   de 9.5.0 (`497c8c2a…194a9c7`) que nomme `gradle-wrapper.properties`.
4. *Non bloquant* — aucun fichier source ne porte d'en-tête de licence
   (156 fichiers `.kt`/`.kts` sur 156) ; seule la mention « GPLv3 » du README
   et de l'écran À propos fixe la version.
5. *Non bloquant* — la commande « conditions F-Droid » de `docs/release.md`
   (`-Dorg.gradle.java.installations.auto-detect=false`) échoue sur un poste
   avec JDK 21 en `JAVA_HOME` : « Cannot find a Java installation … matching
   {languageVersion=21} », même avec `installations.paths`. La build sans ces
   options réussit ; F-Droid ne les passe pas.

**Constats.**
- Licence : `LICENSE` = texte GPLv3 intégral ; README (« [GPLv3](LICENSE) »)
  et À propos (« GNU General Public License version 3 ») nomment la version 3
  sans « ou ultérieure » : `License: GPL-3.0-only`, comme Roue Libre.
- Dépendances : `releaseRuntimeClasspath` ne contient que `androidx.*`,
  `org.jetbrains.*`, `org.jspecify`, `com.squareup.okhttp3`/`okio` et
  `com.google.guava:listenablefuture:1.0` (Apache 2.0, classe vide de
  WorkManager) ; aucun `gms`, `firebase`, `play-services`. Dépôts :
  `google()`, `mavenCentral()`, `gradlePluginPortal()` (plugins seulement),
  `FAIL_ON_PROJECT_REPOS`, pas de foojay ni de `toolchainUrl`.
- Binaires suivis par Git : uniquement `gradle-wrapper.jar` (voir point 3),
  des PNG/WebP (icône, captures) et `data/src/main/assets/communes.tsv`
  (texte, régénérable par `tools/generate_communes.py`). Aucun `.jar`,
  `.aar`, `.so`, `.apk`, `.dex` autre.
- APK release : 2 947 302 octets ; `lib/` = 8 `.so` d'AndroidX (DataStore,
  `graphics.path`) pour 64 Ko sur 4 ABI : un découpage par ABI ne gagnerait
  que ~2 %, il n'est pas à demander. NDK requis pour leur élagage, fixé à
  `28.2.13676358` = `r28c`, repris dans la recette. Aucune classe Google
  propriétaire dans le dex ; seule URL de service dans le dex :
  `https://hubeau.eaufrance.fr/api/v1/qualite_eau_potable/`.
- Manifeste : `INTERNET`, `ACCESS_COARSE_LOCATION`, `POST_NOTIFICATIONS`,
  plus `WAKE_LOCK`, `ACCESS_NETWORK_STATE`, `RECEIVE_BOOT_COMPLETED` de
  WorkManager et la permission interne `DYNAMIC_RECEIVER_NOT_EXPORTED` d'AndroidX
  core. Pas de `MANAGE_EXTERNAL_STORAGE`. Cleartext interdit. Aucune WebView.
  Aucune clé d'API.
- `versionCode = 1`, `versionName = "1.0.0"` en littéraux dans
  `app/build.gradle.kts` : lisibles par `AutoUpdateMode: Version`.
- Fastlane : `en-US` et `fr-FR`, `title`, `short_description`,
  `full_description`, `changelogs/1.txt` dans les limites
  (`tools/check_fastlane.py` : OK) ; icône 512×512 et captures en `en-US` et
  `fr-FR`. La description signale que la traduction est faite par IA, ce qui
  est honnête.
- Catégories : aucune catégorie fine ne décrit la qualité de l'eau ;
  `Science & Education` (« reference ») et `Sports & Health` (« health
  monitoring ») sont les plus proches dans `config/categories.yml`.

**Reproductibilité.** Deux clones neufs du commit `3214ada7`, à deux chemins
différents, construits avec `JAVA_HOME` = OpenJDK 21,
`--no-build-cache --no-configuration-cache`, l'un avec démon et l'autre
`--no-daemon` : `app-release-unsigned.apk` identique à l'octet (`cmp` muet),
SHA-256 `0aac8097417c385e1582d53979f3613b3224e73155bba53eed83203b91726311`.
Même machine et même SDK pour les deux : la comparaison avec le serveur de
build F-Droid reste à faire (`binary:` + `AllowedAPKSigningKeys`, une fois la
clé créée).

**Anti-fonctionnalités.**
- `Tracking` : non. Aucune télémétrie ni rapport de plantage, aucune
  vérification de mise à jour ; la seule requête de fond (alertes
  WorkManager) est désactivée par défaut (`AlertRules`, description Fastlane)
  et ne contacte que Hub'Eau.
- `NonFreeAssets` : non. Le référentiel des communes vient de
  geo.api.gouv.fr et du COG de l'INSEE sous Licence Ouverte Etalab 2.0
  (SPDX `etalab-2.0`) : réutilisation et modification libres, y compris
  commerciales, sous seule condition d'attribution, faite dans À propos, le
  README et la description. Ni clause NC ni ND. Icônes : Material (Apache 2.0)
  et logo propre au projet.
- `NonFreeNet` : non retenue, à défendre. Le drapeau vise un service
  *propriétaire*. Hub'Eau est une plateforme publique nationale (OFB/BRGM),
  gratuite, sans compte, sans clé, dont les CGU placent les jeux de données
  sous Licence Ouverte Etalab : n'importe qui peut les réutiliser et les
  rediffuser, ce que l'on ne peut pas faire avec un service propriétaire.
  Réserve à connaître : le logiciel serveur de Hub'Eau n'est pas publié
  (le dépôt `BRGM/hubeau` ne contient que des exemples et de la doc), et un
  relecteur strict peut s'appuyer là-dessus.
- `TetheredNet` : à trancher par l'auteur. À la lettre, le drapeau
  s'applique (« dépend entièrement d'un service impossible ou difficile à
  remplacer », `hubeau.eaufrance.fr` codé en dur sans option). Contre-argument :
  la recherche de commune et les communes suivies fonctionnent hors ligne, et
  Hub'Eau est la source officielle unique de ces données. Si un relecteur
  exige un drapeau, `TetheredNet` est plus juste que `NonFreeNet`.

**Non vérifié.** Toute la partie appareil : démarrage, fonctions annoncées,
rendu de l'icône, demande effective des permissions au moment de l'usage,
nature exacte de l'écran « Before you start » au premier lancement (bouton
« I understand » : avertissement à reconnaître, pas des conditions à accepter,
d'après les chaînes), capture réseau (aucune case réseau n'est cochée sur la
foi du statique), affichage en anglais, VirusTotal. Build `fdroid build` non
lancée : `fdroidserver` absent du poste, et le dépôt n'est pas public.

**Remarques et questions pour l'auteur** (deux bloquantes, ci-dessus).
- Régénérer le wrapper avec Gradle 9.5.0 pour que le jar corresponde à la
  version annoncée ?
- Ajouter un en-tête `SPDX-License-Identifier: GPL-3.0-only` aux sources, ou
  au moins écrire « GPL-3.0-only » dans le README, pour lever toute ambiguïté ?
- Corriger dans `docs/release.md` la commande « conditions F-Droid »
  (options `-D…auto-detect=false`), qui ne fonctionne pas telle quelle.
- Choisir avant la première soumission entre APK signé par F-Droid et APK
  du projet (`binary:` + `AllowedAPKSigningKeys`) : le choix est définitif.
- `commit:` : les relecteurs demandent en général le hash complet du commit
  tagué plutôt que le nom du tag.

**Contexte.** APK examinée : build release non signée locale,
`0aac8097…91726311`, commit `3214ada7` (non tagué). Outils : Gradle 9.5.0,
AGP 9.3.3, OpenJDK 21, build-tools 37.0.0, NDK 28.2.13676358. Appareil et
capture réseau : aucun (revue statique). Date : 2026-10-25.

### Prompt — B1 : publier le dépôt source

Rends public le dépôt de Potable (`/home/leo/AndroidStudioProjects/Potable`)
sur `https://github.com/mgdx/Potable`.

**Constat.** `https://github.com/mgdx/Potable` répond 404 et le dépôt local
n'a aucun `remote`. La recette fdroiddata (`docs/fdroid/io.github.mgdx.potable.yml`)
pointe `SourceCode`, `Repo` et `IssueTracker` vers cette adresse ; l'écran
À propos aussi (`url_repository` dans `strings.xml`).

**Pourquoi c'est un problème pour F-Droid.** F-Droid construit l'application
depuis un dépôt public ; sans lui, ni la build, ni la revue, ni la mise à jour
automatique ne sont possibles.

**Correction attendue.** Créer le dépôt public `mgdx/Potable` (tickets
activés), ajouter le `remote origin`, pousser la branche principale. Action
manuelle de l'utilisateur : ne rien pousser sans son accord explicite.

**Contraintes.** Vérifier avant de pousser qu'aucun `keystore.properties`,
`*.jks` ni `local.properties` n'est suivi (`git ls-files`). Ne pas réécrire
l'historique.

**Vérification attendue.** `curl -s -o /dev/null -w "%{http_code}" https://github.com/mgdx/Potable`
renvoie 200, et `git ls-remote https://github.com/mgdx/Potable.git` liste la
branche principale.

### Prompt — B2 : étiqueter la version 1.0.0

Pose le tag de la version 1.0.0 de Potable, puis reporte-le dans le brouillon
de recette.

**Constat.** `git tag` ne liste que `sprint-1` à `sprint-6` ; `versionCode = 1`
et `versionName = "1.0.0"` dans `app/build.gradle.kts`. La recette
`docs/fdroid/io.github.mgdx.potable.yml` contient `commit: v1.0.0` et
`UpdateCheckMode: Tags`.

**Pourquoi c'est un problème pour F-Droid.** La build F-Droid se fait sur un
commit précis, et la détection des nouvelles versions lit les tags : sans tag
`vX.Y.Z`, rien à construire ni à suivre. Les tags `sprint-*` risquent en plus
d'être pris pour des versions par `UpdateCheckMode: Tags`.

**Correction attendue.** Une fois la build release validée sur appareil
(`docs/release.md`, étape 4), créer le tag annoté `v1.0.0` sur le commit de
la version et le pousser. Remplacer dans la recette `commit: v1.0.0` par le
hash complet de ce commit (`git rev-parse v1.0.0^{commit}`). Restreindre la
détection des versions avec `UpdateCheckMode: Tags ^v[0-9.]+$`, ou supprimer
les tags `sprint-*` du dépôt public.

**Contraintes.** Ne pas modifier `versionCode` ni `versionName`. Ne pas
pousser sans l'accord de l'utilisateur.

**Vérification attendue.** `git ls-remote --tags https://github.com/mgdx/Potable.git`
montre `refs/tags/v1.0.0` ; le hash de `commit:` dans la recette est égal à
`git rev-parse v1.0.0^{commit}`.
